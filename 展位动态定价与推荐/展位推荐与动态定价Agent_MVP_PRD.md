## 1. 背景与目标

### 1.1 项目背景

会展主办方在展位销售和展位规划过程中，通常需要综合考虑展商行业、预算、参展目标、目标观众、展位位置、历史销售表现、库存紧张度、现场动线和项目收益等因素。传统方式高度依赖销售人员和项目经理的经验，存在以下问题：

- 展商需求理解和展位匹配依赖人工判断，效率不稳定；
- 展位价格解释成本高，销售难以快速说明溢价依据；
- 热区、冷区、库存和销售策略难以在前端演示中形成直观闭环；
- 成熟会展企业已有大量历史数据，但在 Demo 阶段尚无法接入真实内部数据。

因此，本期产品不做完整业务系统，而是做一个轻量 MVP Demo，用模拟数据跑通核心链路：

> 输入展商需求 -> 推荐展位方案 -> 计算建议价格 -> 解释推荐理由 -> 生成销售话术 -> 展示主办方看板。

### 1.2 产品定位

本产品定位为面向会展主办方的“AI 展位销售与定价辅助 Demo”。

它不是正式报价系统，也不是完整展馆 CAD 编辑器，而是用于展示 AI 在展位销售场景中的可落地价值：

- 帮助销售团队更快给展商推荐展位；
- 帮助项目团队理解不同展位的价值差异；
- 用可解释规则展示动态定价逻辑；
- 用自然语言生成推荐理由、风险提示和销售话术；
- 为后续接入真实历史数据、展位图、CRM 和观众数据提供产品雏形。

### 1.3 MVP 核心目标

本期 MVP 目标是快速验证“展位推荐 + 动态定价 + 可解释销售辅助”的业务闭环，而不是建设大而全的平台。

核心目标包括：

1. 用户可以选择或输入展商需求；
2. 系统基于模拟展位资源池推荐 3 个展位方案；
3. 每个方案输出推荐价格、匹配分、推荐理由、风险提示和销售话术；
4. 页面提供简化的展位示意图或展区示意图，支持点击查看展位详情；
5. 主办方看板展示库存、热区、品类需求和动态定价建议；
6. 全流程可在 3-5 分钟内完成会议演示。

## 2. 产品范围

### 2.1 本期范围

本期只做可演示的 MVP Demo，建议采用纯前端或轻量本地服务实现。

本期包含：

- Demo 首页与场景说明；
- 极简展商需求输入面板；
- 3 个预设展商案例；
- 30-50 条模拟展位数据；
- 展位匹配评分规则；
- 动态定价计算规则；
- 3 个推荐方案展示；
- 推荐理由、风险提示、销售话术生成；
- 交互式展位示意图或展区示意图；
- 主办方经营看板；
- 模拟“确认展位”反馈。

### 2.2 本期不做

为保证快速落地，本期明确不做以下能力：

- 登录、权限、多角色管理；
- 真实展馆 CAD 导入与解析；
- 真实展位图编辑器；
- 拖拽式展位规划；
- 真实 CRM、票务、财务或报价系统集成；
- 真实支付、合同、报价审批流程；
- 复杂机器学习模型训练；
- 数据库后台和后台管理系统；
- 多用户协作；
- 对真实展位价格或真实推荐准确性的承诺。

### 2.3 数据边界

Demo 中必须明确说明：

1. 公开信息仅用于构建业务场景背景；
2. 展位图、展位价格、历史销售、热力、库存、匹配分、推荐结果均为模拟数据；
3. 推荐价格是系统演示用建议价，不代表主办方真实报价；
4. 正式落地效果依赖企业真实历史销售数据、展商数据、观众数据、场馆资料和项目复盘资料。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户角色 | 主要诉求 | 本期 Demo 对应能力 |
|---|---|---|
| 主办方销售人员 | 快速给展商推荐合适展位，解释价格和价值 | 展商需求输入、推荐方案、销售话术 |
| 展会项目经理 | 了解库存、热区、冷区和销售策略 | 主办方看板、库存概览、热度排行 |
| 展位规划人员 | 理解不同区域的价值差异 | 展区示意图、热度指标、动态定价规则 |
| 管理层/商务决策者 | 判断 AI 是否有经营价值 | 经营摘要、收益导向指标、后续升级路径 |
| 展商服务团队 | 帮助展商理解推荐理由，减少沟通成本 | 推荐解释、风险提示、替代方案 |

### 3.2 核心演示场景

推荐采用“宠物行业大型展会模拟场景”。原因：

- 宠物展品类丰富，适合展示行业、品类、展区和目标观众匹配；
- 同时包含 B2B 专业观众和 C 端消费者，适合展示不同展商目标；
- 大型展会场景适合展示热区、库存、动态定价和主办方看板。

演示过程中可说明：宠物展只是示例，产品底座可以替换为餐饮展、建材展、制造业展、医疗展、消费品展等行业。

## 4. 产品流程

### 4.1 主流程

1. 用户进入 Demo 首页，了解数据边界和产品价值；
2. 用户进入展商需求输入页；
3. 用户选择一个预设案例，或手动填写展商需求；
4. 用户点击“生成推荐”；
5. 系统基于模拟数据计算展位匹配分；
6. 系统基于定价公式计算每个展位建议价格；
7. 系统输出 3 个推荐方案；
8. 用户点击某个展位，查看详情、价格解释和销售话术；
9. 用户可调整预算、面积或位置偏好后重新推荐；
10. 用户切换到主办方看板查看库存、热区和价格策略。

### 4.2 演示路径

建议会议演示按以下顺序进行：

1. 打开首页，说明当前 Demo 使用公开信息和模拟数据；
2. 选择“宠物食品头部品牌”预设案例；
3. 点击“生成推荐”；
4. 展示 3 个推荐展位方案；
5. 讲解最佳匹配方案的推荐理由；
6. 展示动态价格如何形成；
7. 展示销售话术；
8. 修改预算为“10-20 万”，重新推荐；
9. 切到主办方看板，展示库存、热区、品类需求和价格策略；
10. 说明正式接入真实数据后的升级方向。

## 5. 功能需求

## 5.1 首页 / Demo 说明

### 5.1.1 功能目标

让客户快速理解 Demo 是什么、解决什么问题、当前数据边界是什么。

### 5.1.2 页面内容

首页应包含：

- 产品名称：展位推荐与动态定价 Agent；
- 一句话介绍：根据展商需求、预算和展位资源，自动推荐展位并生成定价建议；
- 当前演示行业：大型宠物行业展会模拟场景；
- 数据说明：公开展会信息 + 模拟展位与历史数据；
- 主要能力：智能推荐、动态定价、理由解释、销售话术、主办方看板；
- 开始按钮：开始推荐。

### 5.1.3 验收标准

- 用户 10 秒内能理解这是一个会展展位推荐与定价 Demo；
- 页面显著位置必须展示“模拟数据”说明；
- 点击“开始推荐”后进入展商需求输入页。

1. 预设案例选择；
2. 表单字段输入。

优先保证预设案例可稳定演示。

### 5.3.1 功能目标

使用模拟展位数据支撑推荐和定价计算。

### 5.3.2 数据规模

| 数据表 | 数量 |

- 推荐逻辑只从 `available` 状态展位中选择；
- 已售和锁定展位可在看板中展示，但不能被推荐；
- 每个推荐展位必须具备计算价格和解释理由所需字段。

## 5.4 展位推荐引擎

### 5.4.1 功能目标

根据展商需求和展位资源，输出 3 个推荐方案。

### 5.4.2 推荐方案类型

| 方案 | 定位 | 输出规则 |
|---|---|---|
| 方案 A：最佳匹配 | 综合匹配度最高，适合作为主推 | 优先选综合评分最高展位 |
| 方案 B：高曝光 | 人流和品牌曝光更强，价格更高 | 优先选交通、人流、曝光指数高的展位 |
| 方案 C：性价比 | 控制预算，适合价格敏感客户 | 优先选预算匹配度高且综合分不低的展位 |

### 5.4.3 匹配评分公式

本期采用规则评分，不训练复杂模型。

```text
综合匹配分 =
行业展区匹配度 × 25%
+ 预算匹配度 × 20%
+ 目标观众匹配度 × 20%
+ 人流曝光潜力 × 15%
+ 展位类型匹配度 × 10%
+ 库存与销售策略 × 10%
```

### 5.4.4 分项评分说明

| 评分维度 | 评分逻辑 |
|---|---|
| 行业展区匹配度 | 展商品类与展区标签越一致，分数越高 |
| 预算匹配度 | 推荐价格落在预算区间内分数最高，超预算则扣分 |
| 目标观众匹配度 | 展区观众标签与展商目标观众重合度越高，分数越高 |
| 人流曝光潜力 | 结合人流指数、入口距离、主通道、论坛区距离计算 |
| 展位类型匹配度 | 展位类型与用户偏好一致得分更高 |
| 库存与销售策略 | 热区稀缺、冷区促销、客户类型策略共同影响 |

### 5.4.5 推荐结果内容

每张推荐卡片必须包含：

| 字段 | 示例 |
|---|---|
| 方案类型 | 最佳匹配 / 高曝光 / 性价比 |
| 展位编号 | E3-A18 |
| 展区 | 宠物食品馆 |
| 面积 | 36㎡ |
| 展位类型 | 双开口角位 |
| 推荐价格 | 168,000 元 |
| 匹配分 | 92 / 100 |
| 人流指数 | 88 / 100 |
| 专业观众匹配度 | 91 / 100 |
| 曝光等级 | A |
| 库存状态 | 可售，仅剩 2 个同类展位 |
| 推荐理由 | 3-5 条 |
| 风险提示 | 1-2 条 |
| 销售话术 | 一段可复制话术 |

### 5.4.6 验收标准

- 每次推荐必须输出 3 个方案；
- 3 个方案不应重复推荐同一个展位；
- 每个方案必须有价格、匹配分、理由、风险和销售话术；
- 改变预算或价格敏感度后，至少一个推荐结果或价格发生变化；
- 推荐理由必须与字段逻辑一致，不能出现无法由数据支撑的描述。

## 5.5 动态定价模块

### 5.5.1 功能目标

用可解释公式生成推荐价格，让用户看到价格不是拍脑袋。

### 5.5.2 定价公式

```text
推荐价格 = 基础价格
× 位置系数
× 人流系数
× 品类热度系数
× 库存紧张系数
× 客户策略系数
× 供需模拟因子
```

### 5.5.3 系数规则

| 因素 | 条件 | 系数示例 |
|---|---|---:|
| 位置等级 | S | 1.20 |
| 位置等级 | A | 1.12 |
| 位置等级 | B | 1.00 |
| 位置等级 | C | 0.90 |
| 人流指数 | 85 以上 | 1.10 |
| 人流指数 | 70-85 | 1.04 |
| 人流指数 | 70 以下 | 0.95 |
| 品类热度 | 高 | 1.08 |
| 品类热度 | 中 | 1.00 |
| 品类热度 | 低 | 0.95 |
| 库存 | 同类展位少于 3 个 | 1.08 |
| 库存 | 同类展位充足 | 1.00 |
| 客户策略 | 头部品牌 | 1.05 |
| 客户策略 | 新客户引入 | 0.97 |
| 客户策略 | 价格敏感 | 0.95 |
| 供需模拟 | Demo 随机波动 | 0.90-1.20 |

### 5.5.4 价格解释

每个推荐方案必须展示价格构成解释，例如：

```text
价格解释：该展位基础价为 135,000 元。由于位于 A 级位置，位置系数为 1.12；人流指数 88，高于热区阈值，人流系数为 1.10；宠物食品当前需求热度较高，品类热度系数为 1.08；同类展位库存较少，库存系数为 1.08。综合计算后，系统建议价格为 168,000 元。
```

### 5.5.5 价格动画

推荐结果页可加入轻量动画：

- 用户点击展位后，价格从基础价滚动到推荐价；
- 动画时长 1-2 秒；
- 动画结束后展示价格构成标签。

### 5.5.6 验收标准

- 每个推荐展位都能展示基础价、推荐价和关键系数；
- 推荐价计算结果可复现；
- 页面明确说明推荐价为 Demo 建议价；
- 不出现“真实成交价”“最终报价”等误导性文案。

## 5.6 展位示意图交互

### 5.6.1 功能目标

通过简化平面图或展区图，直观呈现推荐展位位置和热区分布。

### 5.6.2 实现方式

本期不做真实 CAD 导入，建议使用 SVG 或 Canvas 绘制简化示意图。

功能包括：

- 根据选定场景展示预设场馆/展区底图；
- 高亮系统推荐的 3 个展位；
- 显示更多可选虚拟展位点位；
- 鼠标悬停展示展位编号、面积、类型、基础价；
- 点击展位后右侧面板展示动态价格和推荐解释。

### 5.6.3 状态表达

| 状态 | 视觉建议 |
|---|---|
| 推荐展位 | 高亮描边或发光效果 |
| 可售展位 | 中性色块 |
| 锁定展位 | 灰色或斜纹 |
| 已售展位 | 深灰或不可点击 |
| 热区 | 热力渐变或红橙色背景 |
| 冷区 | 蓝灰色背景 |

### 5.6.4 验收标准

- 推荐展位在图上可被明确识别；
- 点击推荐卡片时，示意图对应展位同步高亮；
- 点击示意图展位时，右侧详情同步更新；
- 页面必须说明地图为简化模拟，不是真实展馆图。

## 5.7 推荐理由与销售话术生成

### 5.7.1 功能目标

把评分和定价结果转化为销售人员能直接使用的自然语言。

### 5.7.2 推荐理由

每个方案输出 3-5 条推荐理由，要求：

- 与展商目标相关；
- 与展位位置、展区、观众匹配、人流、库存相关；
- 不夸大真实效果；
- 使用“适合”“有利于”“建议”这类辅助决策措辞。

示例：

```text
推荐理由：
- 该展位位于宠物食品馆主通道附近，适合以新品曝光和渠道招商为目标的品牌。
- 周边展商以宠物食品和渠道服务商为主，与目标买家匹配度较高。
- 距离论坛活动区较近，有利于承接专业观众流量。
- 当前同类可售展位较少，适合预算充足且追求曝光的展商优先考虑。
```

### 5.7.3 风险提示

每个方案输出 1-2 条风险提示，要求说明潜在限制。

示例：

```text
风险提示：
- 该位置价格高于同面积均值，适合对曝光有明确诉求的展商。
- 主通道附近人流较大，建议展台设计预留足够接待空间。
```

### 5.7.4 销售话术

每个方案输出一段销售话术，可被销售复制使用。

示例：

```text
这个展位适合您这类以新品曝光和渠道招商为目标的宠物食品品牌。它位于食品馆主通道附近，周边专业买家密度较高，也靠近同期活动区。虽然价格略高于普通展位，但它提供的是更高曝光和更强目标客群匹配度。如果您希望在展期快速提升品牌存在感，这是当前比较优先的方案。
```

### 5.7.5 验收标准

- 每个推荐方案都有推荐理由、风险提示和销售话术；
- 话术不出现“保证成交”“一定提升收入”等绝对承诺；
- 如果使用 LLM，必须有兜底模板，避免接口不可用导致演示中断。

## 5.8 主办方看板

### 5.8.1 功能目标

让客户看到该工具不只是单个展商推荐，也可服务主办方内部经营决策。

### 5.8.2 看板模块

#### 模块 1：展位库存概览

展示：

- 总展位数；
- 已售展位；
- 锁定展位；
- 可售展位；
- 热区剩余展位；
- 冷区待售展位。

#### 模块 2：展区热度排行

| 展区 | 热度指数 | 剩余库存 | 价格策略 |
|---|---:|---:|---|
| 宠物食品馆 | 92 | 12 | 可适度溢价 |
| 宠物用品馆 | 84 | 18 | 保持当前价格 |
| 智能设备馆 | 78 | 20 | 对新锐品牌推荐 |
| 供应链馆 | 65 | 35 | 打包权益促进销售 |

#### 模块 3：品类需求热度

展示当前报名或咨询需求模拟：

- 宠物食品：高；
- 宠物用品：高；
- 宠物医疗：中高；
- 智能设备：中；
- 供应链：中；
- 服务机构：低。

#### 模块 4：动态定价建议

展示系统建议：

- 主通道角位：建议上浮 8%-15%；
- 热门品类展区：建议保留高价值展位给重点客户；
- 冷区展位：建议捆绑论坛露出或媒体权益；
- 供应链馆远端展位：建议推给预算敏感型 B 端企业。

#### 模块 5：AI 经营摘要

展示一段模拟管理层摘要：

```text
当前宠物食品馆和宠物用品馆需求热度较高，主通道角位库存不足，建议提高高曝光展位报价区间，并优先匹配头部品牌和新品发布型客户。供应链馆仍有较多中小面积展位，可通过打包采购商邀约、论坛露出和媒体采访权益提升销售转化。
```

### 5.8.3 验收标准

- 看板能展示库存、热度、品类需求和定价建议；
- 看板数据与模拟展位数据一致；
- 看板中的经营摘要明确为模拟分析，不承诺真实业务结论。

## 5.9 确认展位与导出

### 5.9.1 功能目标

为 Demo 补齐“下一步动作”，但不做真实预订流程。

### 5.9.2 功能说明

用户点击“确认展位”后：

- 弹出 Toast：已模拟确认展位；
- 展示选中的展位编号、推荐价格和方案类型；
- 可将结果打印到控制台或生成本地展示卡片；
- 不进行真实支付、锁位或合同流程。

### 5.9.3 验收标准

- 点击确认后有明确反馈；
- 文案必须包含“模拟”或“Demo”；
- 不出现真实交易、预订成功、支付成功等误导性表述。

## 6. 非功能需求

### 6.1 性能要求

| 指标 | 要求 |
|---|---|
| 首页首屏加载 | ≤ 2 秒，优先本地静态资源 |
| 单次推荐计算 | ≤ 2 秒 |

| 推荐结果渲染 | ≤ 1 秒 |

- 会议演示场景下无需登录即可使用；

- 关键按钮文案清晰，如“生成推荐”“重新推荐”“查看价格解释”“复制销售话术”；
- LLM 生成失败时使用本地模板兜底。

### 6.3 兼容性要求

- 支持 Chrome / Edge 最新版本；
- 支持 1440px 及以上会议大屏展示；
- 支持基础响应式布局，移动端可查看但非本期重点。

### 6.4 安全与合规要求

- Demo 不包含真实客户敏感数据；
- 若接入 LLM，不上传真实客户商业数据；
- 所有模拟数据应在页面或文档中明确标识；
- 避免表达“真实定价”“真实推荐”“保证收益”等承诺。

## 9. 技术实现建议

### 9.1 MVP 技术架构

```text
前端 Demo 页面
  -> 展商需求表单
  -> 本地 JSON 模拟数据
  -> 规则评分引擎
  -> 动态定价模块
  -> LLM 或模板生成解释
  -> 推荐结果与看板展示
```

### 9.2 技术选型

结合“快速落地、功能打通”的目标，建议：

- 前端：React / Vue / 原生 JS 均可，优先沿用当前项目已有技术；
- 可视化：SVG、Canvas、ECharts 或 Konva.js；
- 数据：本地 JSON 文件；
- 算法：JavaScript 本地规则函数；
- LLM：可选，如果接口不稳定则使用模板兜底；
- 部署：静态页面即可，支持本地打开或简单 HTTP 服务。

### 9.3 一周内不建议投入

- 后台管理系统；
- 数据库建模；
- 接口联调；
- 机器学习训练；
- CAD 解析；
- 真实系统集成。

## 11. 验收标准

### 11.1 功能验收

- 首页能够说明 Demo 价值和数据边界；
- 3 个预设案例可一键载入；
- 表单必填校验可用；
- 点击生成推荐后输出 3 个不同推荐方案；
- 每个方案包含展位信息、推荐价、匹配分、理由、风险、销售话术；
- 推荐价格可展示基础价和系数解释；
- 展位示意图可高亮推荐展位；
- 主办方看板可展示库存、热度和价格策略；
- 模拟确认展位有反馈。

### 11.2 演示验收

- 完整演示路径控制在 3-5 分钟；
- 不依赖真实后台服务；
- 不因 LLM 接口失败阻塞核心演示；
- 可在无真实客户数据情况下完整跑通；
- 页面中明确标识模拟数据。

### 11.3 业务表达验收

Demo 过程中必须强调：

- AI 不是替代销售，而是增强销售；
- 当前 Demo 是模拟数据，真实价值来自接入企业历史数据；
- 动态定价是内部辅助建议，不是自动对外改价；
- 首期可从一个成熟展会试点，不需要全公司级系统改造；
- 后续可扩展到展位布局优化、历史案例知识库、收益预测等模块。

## 12. 风险与应对

| 风险 | 应对方式 |
|---|---|
| 对方质疑数据真实性 | 明确说明展位、价格、历史销售和热力数据均为模拟数据 |
| 对方认为推荐不够准确 | 强调准确性依赖真实历史数据，当前展示产品能力和建模框架 |
| 对方已有内部系统 | 将 AI 定位为增强层，而不是替换 CRM、票务或展位系统 |
| 动态定价敏感 | 强调为内部辅助建议，不直接面向展商自动报价 |
| 销售团队担心被替代 | 强调 AI 是销售助理，帮助生成推荐和话术，不替代销售判断 |
| LLM 输出不稳定 | 使用本地模板兜底，保证演示链路可控 |
| 一周内范围失控 | 严格遵守本 PRD 的不做范围，不扩展后台和真实集成 |

7. 支持冷区展位促销策略；

11. 支持跨城市、跨场馆、跨展会复制。

## 14. 待确认问题

以下问题不阻塞 MVP，但建议在开发前或评审时确认：

1. Demo 最终面向对象是内部评审、客户会议，还是公开路演？不同场景会影响数据免责声明和话术强度。
2. 当前是否必须接入真实 LLM 接口？如果接口不稳定，建议优先使用模板生成解释。
3. 交付物是否只需要网页 Demo，还是还需要演示讲稿和静态截图备份？
4. 展位示意图需要做到“像真实展馆”，还是只需表达推荐逻辑？本 PRD 建议后者。
5. UI 技术栈是否沿用现有 `output/index.html` 静态实现，还是重建 React/Vue 项目？
6. 是否需要中英文双语版本？当前 PRD 默认中文演示。

## 15. 一句话总结

本期 MVP 应展示一个轻量但完整的 AI 展位销售闭环：

> 输入展商需求，系统基于模拟展位资源和定价规则推荐 3 个展位方案，并输出推荐价格、匹配分、推荐理由、风险提示和销售话术，同时通过主办方看板展示库存、热区和价格策略。

宠物展只是演示案例，真正的产品底座是“展商需求理解 + 展位匹配 + 动态定价 + 可解释推荐 + 销售辅助”，后续可复用于不同会展行业。
