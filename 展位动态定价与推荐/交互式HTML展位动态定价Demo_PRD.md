## 1. 需求重新定义

本 Demo 的目标不是做完整会展管理系统，也不是做真实展位销售平台，而是做一个可现场演示的交互式 HTML Demo。

用户在页面上选择：

- 场馆；
- 会展行业；
- 展区规划偏好；
- 竞争厂商/历史数据模拟条件；
- 展商需求。

系统随后在预设的场馆平面图上生成一组模拟展位，并展示不同位置展位的面积、热度、基础价、动态定价和推荐理由。

同时页面接入一个真实 LLM 助手。助手基于当前 Demo 数据，为用户解释：

- 为什么某些位置价格更高；
- 哪些展位适合某类展商；
- 如何向客户推荐该展位；
- 如果预算不足，有哪些替代方案。

一句话总结：

> 这是一个“场馆平面图 + 展位模拟生成 + 动态定价 + LLM 推荐助手”的可交互 Demo。

## 2. 这个方向是否合乎会展业务逻辑

从会展行业逻辑看，这个 Demo 方向是成立的，而且比单纯“填表推荐展位”更直观。

原因如下：

1. 会展主办方确实需要先确定场馆和展区布局，再对展位进行销售和定价。
2. 展位价格通常不只由面积决定，还受位置、动线、入口、主通道、展区热度、竞品邻近、剩余库存、历史销售速度等因素影响。
3. 不同行业展会的展区结构不同，例如宠物展、餐饮展、建材展、工业展的品类、买家动线和高价值位置都不一样。
4. 主办方在真实业务中会使用场馆平面图或 CAD 图做展位规划；Demo 阶段用预设假平面图模拟是合理的。
5. LLM 不适合直接凭空决定价格，但适合基于已有模拟数据做解释、推荐、话术和问答。

需要注意的边界：

1. Demo 可以模拟“生成展位分布”，但真实项目中展位生成必须受消防通道、承重、主通道宽度、搭建规则、主办方招商策略约束。
2. Demo 可以做“动态定价建议”，但真实项目中价格通常仍需要主办方审批，不应表现成 AI 自动改价。
3. Demo 可以使用 LLM 做推荐助手，但定价计算最好由规则公式完成，LLM 负责解释和销售辅助，避免价格不可控。
4. Demo 可以展示竞品和历史数据影响，但必须明确这些是模拟数据。

因此，推荐产品叙事应是：

> 我们用一个 HTML Demo 模拟真实主办方工作流：选择场馆和行业后，系统自动生成展位布局和动态价格，再由 LLM 助手解释推荐逻辑，帮助销售团队更快完成展位推荐和价格沟通。

## 3. Demo 用户画像

### 3.1 会展主办方项目经理

关注点：

- 不同场馆适不适合某类展会；
- 展区怎么划分；
- 哪些位置是热区；
- 哪些冷区需要促销或权益打包；
- 展位价格是否有依据。

### 3.2 招商销售人员

关注点：

- 某个展商适合哪个展位；
- 如何解释价格；
- 客户嫌贵时如何推荐替代展位；
- 如何快速生成销售话术。

### 3.3 展商或客户方

关注点：

- 为什么这个展位适合我；
- 这个展位贵在哪里；
- 同预算下还有哪些选择；
- 位置、人流、目标客户是否匹配。

## 4. Demo 整体结构

建议做成一个单页 HTML 应用，分为 5 个区域：

| 区域 | 名称 | 作用 |
|---|---|---|
| A | 参数控制区 | 选择场馆、行业、分区策略、历史数据模拟条件 |
| B | 场馆平面图区 | 展示预设场馆平面图和生成的模拟展位 |
| C | 展位详情区 | 点击展位后展示面积、类型、热度、价格、系数 |
| D | 推荐结果区 | 展示系统推荐的 3 个展位方案 |
| E | LLM 助手区 | 基于当前场景回答问题、解释推荐、生成销售话术 |

页面不需要复杂路由，建议一个 HTML 页面完成全部演示。

## 5. 核心交互流程

### 5.1 基础流程

1. 用户打开 HTML Demo；
2. 用户选择一个场馆；
3. 系统加载该场馆的预设平面图；
4. 用户选择会展行业；
5. 用户选择展区规划策略；
6. 用户选择竞争厂商/历史数据模拟条件；
7. 系统在平面图中生成模拟展位分布；
8. 系统为每个展位计算基础属性和动态价格；
9. 用户点击任意展位查看详情；
10. 用户输入或选择展商需求；
11. 系统推荐 3 个展位；
12. LLM 助手解释推荐理由并生成销售话术。

### 5.2 推荐演示路径

建议演示时按以下顺序：

1. 选择“国际会展中心 A 馆”；
2. 选择“宠物行业展”；
3. 选择“按品类分区 + 主通道强化曝光”；
4. 点击“生成展位布局”；
5. 页面出现模拟展位网格、热区和价格；
6. 点击主入口附近大展位，展示高曝光高价格；
7. 点击边角区域小展位，展示性价比价格；
8. 选择展商案例“宠物食品头部品牌”；
9. 系统推荐 3 个展位：高曝光、最佳匹配、性价比；
10. 在 LLM 助手中提问：“如果客户觉得太贵，怎么解释？”；
11. LLM 返回销售话术和替代方案。

## 6. 功能需求

## 6.1 场馆选择

### 6.1.1 功能说明

前端提供 2-3 个预设假场馆。每个场馆有不同的平面结构，用于展示不同场地对展位布局和定价的影响。

### 6.1.2 预设场馆建议

| 场馆 | 特点 | 适合展示 |
|---|---|---|
| 国际会展中心 A 馆 | 矩形大馆，主入口清晰，主通道贯穿 | 标准大型展会布局 |
| 科技博览中心 B 馆 | L 型结构，有明显转角和冷区 | 冷区识别、动线优化 |
| 城市展览中心 C 馆 | 多入口、多功能区，面积较分散 | 多入口热度、分区策略 |

### 6.1.3 场馆数据字段

```json
{
  "venue_id": "venue_a",
  "venue_name": "国际会展中心 A 馆",
  "width": 1200,
  "height": 720,
  "entrances": [
    { "x": 80, "y": 360, "type": "main" }
  ],
  "main_aisles": [
    { "x1": 80, "y1": 360, "x2": 1120, "y2": 360 }
  ],
  "facility_points": [
    { "x": 900, "y": 120, "type": "forum" },
    { "x": 1000, "y": 600, "type": "catering" }
  ],
  "restricted_areas": []
}
```

### 6.1.4 验收标准

- 用户切换场馆后，平面图结构明显变化；
- 不同场馆生成的展位分布和价格结果不同；
- 页面明确说明场馆为模拟平面图。

## 6.2 会展行业选择

### 6.2.1 功能说明

用户选择会展行业后，系统加载该行业的展区类型、目标观众、热度系数和定价规则。

### 6.2.2 预设行业建议

| 行业 | 展区示例 | 价格逻辑特点 |
|---|---|---|
| 宠物行业展 | 宠物食品、宠物用品、医疗健康、智能设备、供应链 | 食品和用品热度高，主通道溢价明显 |
| 餐饮加盟展 | 餐饮品牌、食材供应、设备、饮品、加盟服务 | 试吃区、主通道、洽谈区价值高 |
| 建材家居展 | 地材、门窗、卫浴、定制家居、智能家居 | 大面积展位和样板展示区价值高 |
| 人工智能展 | 大模型、硬件、机器人、行业应用、投资服务 | 头部厂商邻近和发布区价值高 |

### 6.2.3 行业数据字段

```json
{
  "industry_id": "pet",
  "industry_name": "宠物行业展",
  "zones": ["宠物食品", "宠物用品", "医疗健康", "智能设备", "供应链"],
  "hot_categories": ["宠物食品", "宠物用品"],
  "base_heat_multiplier": 1.08,
  "audience_tags": ["经销商", "宠物店", "消费者", "品牌方"]
}
```

### 6.2.4 验收标准

- 切换行业后，展区名称、热度、颜色和推荐逻辑发生变化；
- 不同行业下，同一位置展位价格可以不同；
- LLM 助手能基于当前行业进行解释。

## 6.3 展区规划策略选择

### 6.3.1 功能说明

用户选择展区规划策略后，系统按照不同逻辑在场馆平面图上生成模拟展位和分区。

### 6.3.2 预设策略

| 策略 | 说明 | 适合展示 |
|---|---|---|
| 按品类分区 | 同类展商集中在同一展区 | 专业展常见布局 |
| 主通道优先 | 高价值展位沿主通道和入口布置 | 动态定价和曝光价值 |
| 头部品牌带动 | 将头部品牌放在关键节点，带动周边展位 | 竞品/锚点厂商影响 |
| 性价比均衡 | 避免价格过度集中，兼顾中小展商 | 冷区促销和均衡布局 |

### 6.3.3 验收标准

- 不同策略生成的展位分布有明显差异；
- 主通道优先策略下，主通道附近展位更多或价格更高；
- 头部品牌带动策略下，头部厂商周边展位价格和热度更高。

## 6.4 竞争厂商和历史数据模拟

### 6.4.1 功能说明

Demo 中提供若干模拟变量，用于展示历史数据和竞争厂商对定价的影响。

### 6.4.2 可调参数

| 参数 | 可选值 | 影响 |
|---|---|---|
| 竞品密度 | 低 / 中 / 高 | 同品类竞争越高，部分展商可能避开竞品，也可能因品类集聚提高热度 |
| 历史售卖速度 | 慢 / 中 / 快 | 售卖快的区域价格上浮 |
| 观众热力 | 均匀 / 主入口集中 / 主通道集中 / 活动区集中 | 影响人流系数 |
| 库存紧张度 | 充足 / 正常 / 紧张 | 库存越紧张，价格越高 |
| 头部品牌数量 | 少 / 中 / 多 | 头部品牌周边区域曝光和定价提升 |

### 6.4.3 业务逻辑

- 历史售卖速度快 -> 说明该区域受欢迎 -> 定价上浮；
- 主入口/主通道热力高 -> 曝光价值高 -> 定价上浮；
- 库存紧张 -> 稀缺性提高 -> 定价上浮；
- 竞品密度高 -> 对部分展商是风险，对希望行业集聚的展商是优势；
- 头部品牌邻近 -> 可提高曝光，但也可能带来被竞争压制的风险。

### 6.4.4 验收标准

- 用户调整模拟参数后，展位价格和推荐理由发生变化；
- 价格解释中能展示这些模拟因素的影响；
- LLM 能解释“竞品靠近是优势还是风险”。

## 6.5 模拟展位生成

### 6.5.1 功能说明

系统根据场馆平面图、行业、分区策略和模拟参数，在图上生成展位。

本期不做复杂几何算法，可以使用规则化网格生成：

- 将场馆划分为若干可用区域；
- 沿主通道、入口、活动区、边角区域生成不同尺寸展位；
- 每个展位有坐标、面积、类型和价格属性；
- 使用颜色或标签区分不同展区。

### 6.5.2 展位类型

| 类型 | 面积 | 适合展商 | 定价特点 |
|---|---:|---|---|
| 标准展位 | 9㎡ / 18㎡ | 小型展商、预算敏感客户 | 基础价格低 |
| 角位 | 18㎡ / 36㎡ | 需要一定曝光的品牌 | 位置溢价 |
| 双开口展位 | 36㎡ / 72㎡ | 中大型品牌 | 曝光更高，价格上浮 |
| 岛型展位 | 72㎡ / 100㎡+ | 头部品牌、发布活动 | 高曝光高价格 |
| 边角性价比位 | 9㎡ / 18㎡ | 供应链、小预算展商 | 价格较低，可打包权益 |

### 6.5.3 展位字段

```json
{
  "booth_id": "A-018",
  "x": 420,
  "y": 260,
  "w": 80,
  "h": 60,
  "area": 36,
  "zone": "宠物食品",
  "booth_type": "双开口",
  "location_grade": "A",
  "traffic_score": 88,
  "competition_score": 72,
  "history_score": 90,
  "base_price": 120000,
  "dynamic_price": 168000,
  "status": "available"
}
```

### 6.5.4 验收标准

- 点击“生成展位布局”后，平面图上出现 30-80 个模拟展位；
- 展位大小、颜色、位置能体现展区和价值差异；
- 不同场馆、行业、策略生成结果不同；
- 展位生成结果可重复或可通过“重新生成”刷新。

## 6.6 动态定价展示

### 6.6.1 功能说明

系统为每个展位计算基础价和动态价，并展示价格构成。

### 6.6.2 推荐公式

```text
动态价格 = 基础价格
× 位置系数
× 面积/类型系数
× 行业热度系数
× 人流热力系数
× 历史售卖系数
× 竞品/头部品牌邻近系数
× 库存紧张系数
```

### 6.6.3 系数解释

| 系数 | 说明 |
|---|---|
| 位置系数 | 入口、主通道、转角、活动区附近溢价 |
| 类型系数 | 角位、双开口、岛型展位价值更高 |
| 行业热度系数 | 当前行业或品类热度越高，价格越高 |
| 人流热力系数 | 预估人流越高，价格越高 |
| 历史售卖系数 | 历史售卖越快，价格越高 |
| 竞品/头部品牌邻近系数 | 头部品牌带动周边溢价，竞品过密可能产生风险扣分 |
| 库存紧张系数 | 剩余少则上浮，库存多则维持或下调 |

### 6.6.4 页面展示

点击展位后，详情区展示：

- 展位编号；
- 所属展区；
- 面积；
- 展位类型；
- 基础价格；
- 动态价格；
- 价格变化百分比；
- 位置系数；
- 行业热度系数；
- 人流热力系数；
- 历史售卖系数；
- 竞品影响；
- 库存影响；
- 一段自然语言解释。

### 6.6.5 验收标准

- 每个展位都能查看动态价格；
- 价格变化有清晰原因；
- 高价值位置价格明显高于边角位置；
- 页面明确说明价格为模拟建议价。

## 6.7 展商需求与展位推荐

### 6.7.1 功能说明

除全局生成展位外，Demo 还应提供一个展商需求输入区，用于触发推荐。

### 6.7.2 展商输入字段

| 字段 | 示例 |
|---|---|
| 展商名称 | 宠鲜粮品牌 A |
| 展商类型 | 头部品牌 / 新锐品牌 / 供应链企业 / 海外品牌 |
| 所属品类 | 宠物食品 / 智能设备 / 供应链 |
| 预算 | 5-10 万 / 10-20 万 / 20-50 万 / 50 万以上 |
| 期望面积 | 9㎡ / 18㎡ / 36㎡ / 72㎡ / 100㎡以上 |
| 参展目标 | 品牌曝光 / 渠道招商 / 新品发布 / B 端采购 |
| 位置偏好 | 主通道 / 入口附近 / 同品类展区 / 性价比区域 |
| 是否介意竞品邻近 | 介意 / 不介意 / 希望靠近同类展商 |

### 6.7.3 推荐结果

系统推荐 3 个方案：

| 方案 | 定位 |
|---|---|
| 高曝光方案 | 人流、入口、主通道优势强，价格较高 |
| 最佳匹配方案 | 综合匹配展商目标、预算、品类和位置 |
| 性价比方案 | 价格更低，但仍满足核心需求 |

每个方案展示：

- 展位编号；
- 面积；
- 展区；
- 动态价格；
- 匹配分；
- 推荐理由；
- 风险提示；
- 可复制销售话术。

### 6.7.4 验收标准

- 推荐展位必须来自当前生成的平面图；
- 点击推荐卡片时，平面图对应展位高亮；
- 预算变化后推荐结果应有变化；
- 竞品偏好变化后推荐理由应有变化。

## 6.8 LLM 推荐助手

### 6.8.1 功能说明

页面提供一个真实接入 LLM 的助手，用于基于当前场景进行推荐和解释。

LLM 不负责底层定价计算，定价由前端规则引擎完成。LLM 负责：

- 解释当前展位为什么贵；
- 推荐适合某个展商的展位；
- 生成销售话术；
- 分析竞品邻近的利弊；
- 给出替代方案；
- 生成主办方经营建议。

### 6.8.2 助手上下文

调用 LLM 时，应传入当前上下文：

```json
{
  "venue": "国际会展中心 A 馆",
```

### 6.8.3 预设问题

助手区提供快捷问题：

- 为什么这个展位价格更高？
- 这个展位适合什么类型的展商？
- 如果客户觉得贵，销售该怎么解释？
- 预算 10-20 万时推荐哪个展位？
- 竞品在旁边是风险还是机会？
- 主办方应该如何处理冷区展位？

### 6.8.4 回答边界

LLM 回答必须遵守：

- 明确这是基于模拟数据的建议；
- 不承诺真实成交结果；
- 不说“保证提升收入”；
- 不直接给出真实报价承诺；
- 不脱离当前场馆、行业和展位数据胡编。

### 6.8.5 兜底机制

如果 LLM 接口失败：

- 页面展示“助手暂不可用”；
- 推荐卡片仍使用本地模板展示推荐理由和销售话术；
- 不影响核心 Demo 演示。

### 6.8.6 验收标准

- 助手能读取当前选中展位或推荐方案上下文；
- 助手回答与当前数据一致；
- 助手能生成可用销售话术；
- LLM 不可用时核心推荐流程仍可运行。

## 8. 技术建议

### 8.1 最小实现方式

如果目标是快速完成 HTML Demo，建议：

- 使用单个 `index.html`；
- CSS 写在 `styles.css`；
- 交互逻辑写在 `app.js`；
- 场馆、行业、规则和展商数据写在 JS 常量或 JSON 文件中；
- 场馆平面图使用 SVG 绘制；
- 展位使用 SVG rect 或 Canvas 绘制；
- LLM 接口通过一个配置项接入。

## 10. 对外演示话术

建议这样介绍：

```text
这个 Demo 模拟的是会展主办方在展位规划和销售过程中的核心工作流。

真实业务中，主办方会预先导入或维护场馆平面图、展区规划、历史销售、展商画像和观众热力等数据。当前演示版本使用几套假的场馆平面图和模拟数据，目的是展示产品逻辑。

用户选择场馆、行业和分区策略后，系统会自动生成模拟展位分布，并根据位置、人流、行业热度、竞品邻近、历史售卖速度和库存紧张度计算动态价格。

随后，销售可以输入某个展商的预算和参展目标，系统推荐高曝光、最佳匹配和性价比三个方案。LLM 助手负责解释推荐原因、生成销售话术，并回答客户关于价格和位置的问题。

这不是一个真实报价系统，而是一个 AI 辅助规划和销售决策的 Demo。正式落地时，可接入企业真实场馆图、历史成交、CRM 和观众数据，让推荐和定价更贴近实际业务。
```

## 11. 关键产品判断

本 Demo 最重要的不是算法多复杂，而是让客户直观看到：

1. 场馆结构会影响展位价值；
2. 行业类型会影响展区规划和价格；
3. 竞品、头部品牌、历史销售和库存会影响动态定价；
4. AI 可以把这些因素解释成销售能用的话术；
5. 正式接入真实数据后，这套逻辑可以升级为主办方的智能展位销售助手。

## 12. 一句话总结

本 Demo 应做成一个可交互 HTML 页面：

> 用户选择场馆、行业和展区策略后，系统在预设平面图上生成模拟展位分布，并根据位置、人流、行业热度、竞品和历史数据计算动态价格；随后用户输入展商需求，系统推荐合适展位，并由真实 LLM 助手解释推荐理由和销售话术。
