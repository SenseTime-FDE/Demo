## 1. 背景与目标

### 1.1 业务背景

WAGAS 于 1999 年率先在中国开创健康轻食概念，以"健康、美味、时尚"为核心价值，目前是中国最大的独立西式休闲餐饮集团之一，全国约 250 家门店，选址聚焦核心商圈与中高档写字楼，老客占比高达约 80%，客单价相对较高（主力价格带 78–85 元）。菜单覆盖能量碗、沙拉、三明治&卷、东南亚主食、意面、西点、鲜榨果汁、咖啡等全时段品类。

WAGAS 的目标人群是追求健康的都市白领与健身/塑形人群。这类用户对饮食有明确且较高的标准——膳食均衡、热量与宏量营养素（蛋白质/碳水/脂肪）控制、低糖低钠、食材新鲜等。但现状是：

- **决策成本高**：用户每天面对"今天吃什么才健康又不重复"的选择疲劳。
- **专业门槛高**：普通用户不懂如何把"减脂/增肌/控糖"目标换算成每餐的具体菜品与份量。
- **缺乏连续性**：单次点餐无法形成持续的饮食管理，复购依赖用户自驱。
- **菜单与目标脱节**：现有点餐流程按品类陈列，不按用户健康目标组织，转化与客单价提升受限。

### 1.2 产品愿景

把 WAGAS 的菜单变成一位"懂你健康目标的私人营养顾问"——用户告诉智能体自己的身体状况与健身/饮食目标，智能体结合 WAGAS 菜单，自动生成可执行的饮食计划、推荐菜品与一周套餐，并在持续使用中不断优化，帮助用户实现健康饮食管理，同时为 WAGAS 提升客单价、复购率与会员价值。

### 1.3 产品目标（按优先级）

1. **用户价值**：降低健康饮食的决策与专业门槛，让用户"按目标吃、吃得放心、吃得省心"。
2. **转化与客单价**：通过计划化推荐与套餐组合，提升单次客单价与连带率。
3. **复购与留存**：通过订阅计划、周套餐预订与数据驱动召回，提升 30/90 日复购率。
4. **会员与 LTV**：通过付费订阅与会员体系，沉淀高价值用户，提升用户生命周期价值（LTV）。
5. **数据资产**：沉淀用户健康画像与饮食偏好数据，反哺选品、定价与精准营销。

### 1.4 衡量目标（北极星与关键指标）

- **北极星指标**：通过智能助手完成的订单 GMV 占比 / 助手月活跃用户（MAU）。
- 智能助手渗透率：使用过助手的下单用户 / 总下单用户 ≥ 40%（上线 6 个月）。
- 助手引导订单客单价较普通下单提升 ≥ 15%。
- 周套餐/订阅用户 30 日复购率 ≥ 55%。
- 付费订阅渗透率 ≥ 8%（活跃用户）。

## 2. 市场与竞品分析

### 2.1 机会点

健康饮食人群规模持续增长，但市场上"专业营养指导"与"便捷点餐"长期割裂：营养 App（如各类卡路里记录工具）懂营养但不能直接下单；外卖/点餐平台能下单但不懂用户的健康目标。WAGAS 同时拥有**健康定位的菜单 + 门店履约能力 + 高粘性会员**，是少数能把"营养顾问"与"即时点餐/履约"闭环打通的品牌，具备天然壁垒。

### 2.2 竞品对照

| 维度 | 营养记录类 App | 外卖/点餐平台 | 普通品牌官网/点餐页 | WAGAS 智能助手（本产品） |
| --- | --- | --- | --- | --- |
| 懂健康目标 | 强 | 弱 | 弱 | 强 |
| 直接下单履约 | 无 | 强 | 强 | 强 |
| 菜品营养可信度 | 用户自填 | 不透明 | 一般 | 官方现制、营养可标注 |
| 计划连续性 | 中 | 无 | 无 | 强（订阅+周套餐） |
| 数据闭环 | 单点 | 平台所有 | 弱 | 品牌自有闭环 |

### 2.3 差异化策略

以"目标驱动"重构点餐体验，替代"品类驱动"；以"计划+订阅"替代"单次交易"；以"官方营养数据"建立专业信任。

## 3. 目标用户与画像

### 3.1 用户分层

| 分层 | 占比假设 | 核心诉求 | 产品侧重 |
| --- | --- | --- | --- |
| 健身塑形族（增肌/减脂） | 30% | 精准宏量营养素、蛋白质达标 | 目标换算、营养可视化、训练日适配 |
| 健康管理族（控糖/控压/轻断食） | 25% | 低GI、低钠、均衡 | 健康标签筛选、医学友好提示 |
| 忙碌白领（省心健康） | 35% | 不想纠结、快速、不重复 | 一键计划、周套餐、智能不重样 |
| 尝鲜/轻度健康关注 | 10% | 好吃且不太罪恶 | 轻推荐、热量提示、社交玩法 |

### 3.2 典型用户画像

**画像 A — Vivian，28 岁，外企市场经理**
- 目标：3 个月减脂 5kg，每日热量缺口约 400kcal。
- 痛点：午餐时间紧，不会算热量，常点重复，担心吃多。
- 期望：打开网页，助手直接告诉她"今天午餐吃这个，约 480kcal、蛋白 32g"，一键下单。

**画像 B — Leo，32 岁，程序员 + 健身爱好者**
- 目标：增肌期，每日蛋白质 ≥ 150g。
- 痛点：训练日/非训练日营养需求不同，外食难达标。
- 期望：按训练计划自动调整推荐，周套餐自动配齐蛋白缺口。

**画像 C — 张姐，45 岁，关注血糖管理**
- 目标：控糖、低GI 饮食。
- 痛点：看不懂菜品成分，怕踩雷。
- 期望：助手只推荐适合她的菜，明确标注糖/钠，规避禁忌。

### 3.3 用户场景（User Story 摘选）

- 作为减脂用户，我希望助手根据我的目标推荐每餐菜品和份量，这样我不用自己计算热量。
- 作为忙碌白领，我希望一键预订下一周的午餐套餐，这样我每天不用重复决策。
- 作为增肌用户，我希望训练日能自动获得高蛋白推荐，这样我的营养能达标。
- 作为会员，我希望付费订阅后获得更专业的营养方案和专属价，这样物有所值。
- 作为社交活跃用户，我希望和朋友一起打卡健康饮食并获得奖励，这样更有动力坚持。

## 4. 产品整体方案

### 4.1 产品定位一句话

"一个懂你健康目标的 AI 营养顾问，把 WAGAS 菜单变成你的私人饮食计划。"

### 4.2 核心闭环

采集（健康目标与身体数据）→ 生成（个性化饮食计划）→ 推荐（菜品/周套餐）→ 下单（即时点餐/订阅履约）→ 反馈（打卡、进度、营养摄入）→ 优化（基于数据持续迭代推荐）。该闭环每循环一次，用户画像更精准、推荐更贴合、复购更自然。

### 4.3 功能地图

```
WAGAS 智能点餐助手
├── A. 智能问诊与画像建档（输入层）
├── B. AI 营养计划引擎（核心大脑）
├── C. 智能点餐推荐（即时转化）
├── D. 一周套餐预订与订阅（复购引擎）
├── E. 会员订阅与付费计划（商业化）
├── F. 健康打卡与营养追踪（粘性）
├── G. 数据驱动召回与精准营销（复购）
├── H. 社交、社区与裂变（增长）
└── I. 后台与数据中台（支撑）
```

## 5. 核心功能需求（详述）

### 5.A 智能问诊与画像建档

**目标**：用最低的填写成本，建立可驱动推荐的用户健康画像。

**功能点**：
- **首次引导问诊（对话式）**：智能体以对话形式逐步采集，避免长表单。采集字段：
  - 基础信息：性别、年龄、身高、体重（必填）；体脂率、静息心率（选填）。
  - 健身目标：减脂 / 增肌 / 维持 / 塑形 / 控糖 / 控压 / 轻断食（单选+程度）。
  - 目标强度：温和 / 标准 / 激进（影响热量缺口/盈余幅度）。
  - 饮食偏好与禁忌：素食/纯素、忌口（海鲜、牛肉、香菜等）、过敏原（坚果、麸质、乳糖等）、宗教饮食。
  - 口味偏好：辣度、亚洲/西式倾向、咖啡因接受度。
  - 生活作息：用餐时段、训练频率与时间、预算区间。
- **自动营养目标换算**：依据 Mifflin-St Jeor 公式估算 BMR，结合活动系数得 TDEE，再按目标生成每日热量目标与宏量营养素分配（蛋白/碳水/脂肪比例）。
- **画像可编辑**：随时在"我的健康档案"修改；支持体重周期记录以动态校准。
- **隐私与合规**：健康数据单独授权弹窗，明确用途、存储与撤回方式（详见第 9 章）。
- **冷启动兜底**：跳过详细问诊的用户，仅按"减脂/增肌/均衡"三大模板给出基础推荐。

**验收标准**：完成问诊 ≤ 90 秒；生成的每日热量目标与第三方营养工具误差 ≤ 10%；禁忌项 100% 在后续推荐中被过滤。

### 5.B AI 营养计划引擎（核心大脑）

**目标**：把用户目标转译为可执行、可下单、不重样的饮食计划。

**功能点**：
- **每日计划生成**：按用户每日热量与宏量目标，将三餐（及加餐）拆解为目标区间，匹配 WAGAS 菜品组合，保证全天营养达标。
- **一周计划生成**：自动排布 7 天，控制重复度（同一主菜 7 天内不超过 N 次），兼顾多样性与营养均衡。
- **训练日适配**：识别用户训练日，自动上调蛋白与碳水（训练后窗口推荐）。
- **动态校准**：根据打卡完成度、体重变化、实际下单，每周微调计划（强化学习/规则引擎结合）。
- **可解释性**：每条推荐附"为什么推荐"（如"高蛋白、低于你的午餐热量上限、符合控糖目标"）。
- **替换与自定义**：用户可对任一餐"换一个"，引擎在约束内给出等效替代。
- **营养可视化**：日/周营养雷达图、热量进度环、宏量营养素达标度。

**算法说明（产品视角）**：
- 第一层：硬约束过滤（禁忌、过敏、预算、时段供应）。
- 第二层：营养目标匹配（线性规划/背包近似，最小化与目标的偏差）。
- 第三层：偏好与多样性排序（协同过滤 + 多样性惩罚）。
- 第四层：商业策略加权（高毛利、新品、临期/促销在不违背健康约束前提下适度提权，需可配置且透明）。

**验收标准**：生成的每日计划全天热量偏差 ≤ ±8%、蛋白达标率 ≥ 90%；周计划重复度可控；"换一餐"响应 ≤ 2 秒。

### 5.C 智能点餐推荐（即时转化）

**目标**：把计划无缝转化为订单，最大化转化与连带。

**功能点**：
- **首页"今日推荐"**：进入网页即按当前时段、用户目标推送"今天这一餐"卡片，含菜品、热量、宏量、价格、推荐理由，一键加入购物车。
- **整餐打包推荐**：主菜+饮品+加餐的"营养均衡套餐"，相比单点提升客单价；明确展示组合后总营养。
- **连带与升级提示**：在不破坏营养目标前提下推荐"加 1 份蛋白小食达标蛋白""换大份/小份更贴合你的热量"。
- **门店与时段感知**：结合最近门店库存、备餐时间、全时段菜单（早餐/brunch/午餐/下午茶/轻晚餐）推荐。
- **对话式点餐**：用户可直接说"我想吃个高蛋白午餐，预算 80 以内"，助手返回可下单方案。
- **拒绝与替换闭环**：用户划掉不想要的，助手即时补位，记录负反馈优化画像。

**验收标准**：今日推荐点击率 ≥ 25%；推荐到下单转化率较常规入口提升 ≥ 15%；助手订单平均连带商品数较普通订单提升 ≥ 0.5。

### 5.D 一周套餐预订与订阅（复购引擎）

**目标**：把单次交易升级为持续履约，锁定复购与现金流。

**功能点**：
- **周套餐生成与预订**：基于周计划，一键生成"5 天午餐套餐 / 7 天三餐套餐"，用户可整周预订。
- **灵活配置**：选择天数、餐段、配送或自提门店、每日送达时间窗；支持工作日跳过/节假日暂停。
- **每日可微调**：预订后每日截单前可换菜、跳过、暂停一天，余额顺延。
- **套餐定价策略**：周套餐相较单点提供轻折扣或赠饮，提升锁单率与客单价；预付沉淀资金。
- **自提/配送履约**：与门店 POS、库存、配送系统打通，生成备餐排程。
- **续订与自动滚动**：到期前提醒续订；可开启"自动生成下一周计划"无感续订（用户可关）。

**验收标准**：周套餐用户次周续订率 ≥ 45%；预订流程 ≤ 4 步完成；改单/跳过操作即时生效。

### 5.E 会员订阅与付费计划（商业化核心）

**目标**：用付费订阅沉淀高价值用户，提升 ARPU 与 LTV。

**分层设计**：

| 层级 | 价格（示意） | 核心权益 |
| --- | --- | --- |
| 免费版 | ¥0 | 基础目标换算、每日单餐推荐、有限"换一餐"次数 |
| 健康会员（月/季/年） | ¥29/月起 | 完整周计划、无限换餐、营养追踪报告、会员价、专属新品试吃 |
| 私教营养版（高阶） | ¥99/月起 | 深度个性化方案、训练日精细适配、人工营养师在线答疑（每月N次）、专属客服 |

**功能点**：
- **付费墙设计**：免费版给足"啊哈时刻"（首份计划体验），高级能力（周计划/无限换餐/深度报告/专属价）作为付费转化点。
- **会员专属价与积分加倍**：订阅用户享菜品折扣、积分加速、生日礼、优先备餐。
- **订阅管理**：开通、升级、降级、暂停、退订全流程自助，符合自动续费合规要求（明确告知、可随时取消）。
- **企业版（B 端延展）**：面向写字楼企业的团体健康餐订阅（员工福利），按席位计费，后台统一管理——契合 WAGAS 写字楼选址优势。

**验收标准**：免费转付费率 ≥ 8%；付费用户 90 日留存 ≥ 60%；退订流程符合各支付渠道自动续费/连续扣款合规规范。

### 5.F 健康打卡与营养追踪（粘性）

**目标**：让用户"看得见进步"，提升日活与情感粘性，反哺画像。

**功能点**：
- **饮食打卡**：下单即自动计入当日摄入；非 WAGAS 餐食可手动/拍照快速记录（识别为大致热量）。
- **进度看板**：体重曲线、热量缺口/盈余、宏量达标度、连续打卡天数（streak）。
- **周/月营养报告**：达标率、改进建议、与目标的差距，付费版更深度。
- **成就与提醒**：连续达标徽章、目标里程碑、温和的健康提醒（避免任何鼓励极端节食的措辞，见 9.3）。

**验收标准**：打卡用户次日留存显著高于未打卡用户；周报打开率 ≥ 30%。

### 5.G 数据驱动召回与精准营销（复购）

**目标**：用行为与健康数据做精准触达，唤醒沉默用户、提升复购与交叉销售。

**功能点**：
- **智能召回**：识别 R/F/M 与计划中断信号，按场景推送（"你的减脂计划已暂停 3 天，今天来一份 480kcal 午餐？"）。
- **场景化推送**：天气、时段、训练日、节气（如夏季轻断食、冬季暖碗）触发个性化优惠/推荐。
- **交叉与向上销售**：基于历史营养缺口推荐互补品类（如蛋白不足→推荐蛋白碗/希腊酸奶）。
- **生命周期营销**：新客 7 日转化旅程、活跃维稳、流失预警与挽回券。
- **可控与可解释**：所有推送频控、可一键关闭；营销不得违背用户健康目标（如不向减脂用户高频推甜品）。

**验收标准**：召回触达点击率 ≥ 8%；沉默用户 30 日回流率提升 ≥ 5 个百分点；推送投诉/退订率 < 1%。

### 5.H 社交、社区与裂变（增长）

**目标**：以低成本社交玩法获客与提频。

**功能点**：
- **健康打卡分享**：一键生成精美营养卡片/成就海报，支持保存图片、复制链接及分享至微信/社交平台，海报内嵌专属邀请二维码与短链裂变。
- **好友 PK 与组队**：与好友进行连续打卡、达标天数 PK；组队挑战完成共同领奖。
- **社区内容**：健康食谱、用户食评、营养知识，UGC + 官方 PGC，增强专业心智。
- **拉新奖励**：邀请好友各得券/积分/会员体验；老带新阶梯奖励。
- **拼单与团购**：同写字楼/社区拼周套餐享团购价，契合写字楼场景，降低配送成本。

**验收标准**：分享率 ≥ 10%；邀请带来的新客占比 ≥ 15%；裂变获客成本低于常规投放。

### 5.I 后台与数据中台（支撑）

**目标**：支撑运营对菜品、营养、计划、定价、推荐策略的可配置管理。

**功能点**：
- **菜品营养库管理**：每道菜的热量、宏量营养素、过敏原、标签（高蛋白/低GI/素食等）、时段供应、门店库存、毛利。
- **推荐策略配置**：商业加权系数、新品/促销提权、各目标人群的策略开关（可灰度/AB）。
- **套餐与订阅管理**：套餐模板、价格、库存、履约排程。
- **营销与人群运营**：人群圈选、券、推送、AB 实验。
- **数据看板**：北极星、转化漏斗、客单价、复购、订阅、营养达标等核心指标。

**验收标准**：菜品上下架与营养信息更新实时生效；策略调整支持灰度与回滚。

## 6. 关键用户流程

### 6.1 新用户首次使用（建档→首单）

```
打开网页
  → 智能体欢迎 + 价值说明
  → 对话式问诊（目标/身体/禁忌/预算）  [可跳过，走模板]
  → 自动生成每日热量与宏量目标
  → 展示"今日推荐这一餐"（含理由/营养/价格）
  → 一键加购 → 选门店/时段 → 下单支付
  → 引导：开启周计划 / 体验会员
```

### 6.2 老用户日常点餐

```
打开网页
  → 首页"今日推荐"按时段直达
  → 满意：一键下单 ；不满意：换一餐 / 对话式调整
  → 下单 → 自动计入当日营养打卡
  → 查看进度环与达标度
```

### 6.3 周套餐预订与履约

```
进入"周计划"
  → AI 生成下周 5/7 天计划（可逐餐替换）
  → 配置餐段/门店/送达时间/跳过日
  → 预付下单（享套餐价/赠饮）
  → 每日截单前可改菜/跳过
  → 门店按排程备餐 → 自提或配送
  → 到期前提醒续订 / 自动续订（可关）
```

### 6.4 会员订阅转化

```
免费用户触达付费点（周计划/无限换餐/深度报告/会员价）
  → 展示权益对比与试用
  → 选择月/季/年 → 在线支付开通（微信/支付宝/银行卡等）
  → 解锁高级能力 → 订阅管理（升/降/停/退自助）
```

### 6.5 信息架构（导航）

响应式布局：PC 端采用顶部主导航 + 左侧栏，移动端浏览器自适应为顶部导航 + 底部 Tab。

```
主导航：
  [今日]  AI 推荐、今日营养进度、快速下单
  [计划]  每日/每周计划、订阅管理、套餐预订
  [社区]  打卡、PK、食谱、UGC
  [我的]  健康档案、订单、会员、积分、设置与隐私
全局入口：AI 对话助手（悬浮按钮，随处可唤起）
```

## 8. 技术方案与依赖（产品视角）

### 8.1 系统模块

- **前端**：响应式 Web 应用（React/Vue + TypeScript），PC 与移动端浏览器自适应；可选 PWA 支持（添加到主屏、离线缓存、消息推送），悬浮 AI 助手对话组件。
- **AI 层**：营养计划引擎（规则+优化算法+推荐模型）、对话式 LLM 编排（意图识别、约束抽取、工具调用下单）、可解释模块。
- **业务中台**：菜品营养库、用户健康画像、订单、套餐/订阅、营销、会员积分。
- **数据中台**：埋点采集、用户画像、AB 实验、指标看板。
- **履约对接**：门店 POS、库存、备餐排程、配送（自有/三方）。
- **支付**：聚合在线支付（微信支付、支付宝、银行卡等），支持连续扣款/预付。
- **账号体系**：手机号/邮箱注册登录，支持微信、支付宝等第三方 OAuth 授权登录，多端登录态同步。

### 8.2 关键技术与数据依赖

- **菜品营养标准化数据**：每道菜的标准营养成分是整个产品的地基，需营养师/供应链共建并持续维护（最高优先级依赖）。
- **画像与推荐**：冷启动模板 + 行为数据迭代；多样性与商业加权可配置。
- **LLM 安全**：约束在 WAGAS 菜单与健康范畴内，禁止给出医疗诊断/极端节食建议（见 9.3）。
- **门店履约联调**：备餐时间、库存实时性是周套餐体验的关键。

### 8.3 非功能性需求

- 性能：推荐/换餐响应 ≤ 2s；首页首屏 ≤ 1.5s。
- 可用性：核心下单链路可用性 ≥ 99.9%。
- 可扩展：营养库与策略支持多品牌/多区域扩展。
- 兼容：覆盖主流桌面与移动浏览器（Chrome、Safari、Edge、微信内置浏览器等）及主流分辨率，响应式适配。
- SEO 与可访问性：关键页面支持 SEO 收录，符合基础无障碍（a11y）规范。

## 9. 合规、风险与边界

### 9.1 数据隐私与合规

- 健康数据属敏感个人信息，需单独、明示授权，遵循《个人信息保护法》最小必要原则；提供查看、导出、删除与撤回授权入口。
- 数据加密存储与传输，访问最小授权；第三方数据共享需明确告知。

### 9.2 商业化合规

- 在线支付自动续费/连续扣款需显著告知、可随时取消、扣费前提醒，遵守各支付渠道与监管规则。
- 价格与权益清晰，避免诱导，退订无障碍。

### 9.3 健康与伦理边界（重要）

- 助手仅提供一般性饮食建议，**不提供医疗诊断或治疗方案**；涉及疾病（如糖尿病、孕期等）明确提示咨询专业医师。
- **不得鼓励极端节食、过度热量限制或不健康减重**；热量缺口设上限，对异常低 BMI/目标进行温和提示与拦截。
- 推荐措辞保持正向、非评判，避免引发饮食焦虑。
- 营养数值标注须基于真实数据，避免误导性健康声称。

### 9.4 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 营养数据不准/不全 | 推荐失信、用户流失 | 营养师共建+审核流程，标注置信度，持续校准 |
| 推荐过度商业化伤害信任 | 专业心智受损 | 商业加权设阈值、透明可解释、健康约束优先 |
| 冷启动数据不足 | 推荐不准 | 模板兜底 + 快速反馈学习 |
| 履约能力跟不上订阅 | 体验崩塌 | MVP 限门店/限量灰度，跑通再扩 |
| 付费转化不及预期 | 商业化承压 | 强化免费啊哈时刻，AB 优化付费墙 |
| 隐私合规问题 | 法律与口碑风险 | 合规前置、单独授权、最小必要 |
